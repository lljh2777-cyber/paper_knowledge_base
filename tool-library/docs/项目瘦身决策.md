# 项目瘦身决策

项目目标是方便存储文献、阅读文献、理解文献和查找知识点。四个目标及默认流程已于 2026-11-19 确认。文末逐项记录外围功能的决策与影响。

## 2026-11-19　存储文献（已确认，外部目录直读待实现）

日常流程从 Paper Clipper 开始。它把论文网页保存到本机的 `E:\Literature_translation`，翻译项目在论文目录中生成中文译文。用户希望在当前 Obsidian 知识库直接阅读这份原文和译文，省去复制文件夹和二次入库。

| 保留的能力 | 使用时应有的表现 |
|---|---|
| 文献目录和查找 | 指定一次外部文献目录。打开或刷新文献库时发现新论文，复用已有书目信息，可按标题或 DOI 查找。 |
| 原文、译文和图片 | 剪藏完成即可打开英文原文，并按原目录解析图片。译文就绪后，同一文献条目可以打开中英对照。 |
| 阅读记录 | 阅读位置、批注、摘录与理解笔记由当前知识库保存，关联到实际阅读的文献和语言版本。原文和译文继续由各自的工具维护。 |
| 文件变化后的找回 | 论文文件夹移动或改名后可重新定位。译文更新时保留历史批注，无法确认原句位置的记录提示复核。 |

网页剪藏完成即满足存储目标。日常流程省去重复书目登记、再次获取全文、Markdown 转换和原文包复制。摘要、初步论文笔记或知识卡片留到阅读时按需生成。只有独立 PDF 的文献可作为例外保留本地打开入口，确有正文提取需求时再使用 MinerU。

验收场景：今天剪藏一篇论文，文献库里能打开英文和配图；次日翻译完成，仍从同一条目打开中英对照；下周再读，可以恢复阅读位置，找回当时的批注。当前 Reader 的手动双栏选择器面向当前 Vault 内的文件，直接读取外部目录并把批注保存回当前 Vault 是后续实现目标。

## 2026-11-19　阅读文献（已确认的产品方向）

用户通常顺着中文译文往下读，需要随时看同一段英文原文。打开已有可靠中英配对的论文时，默认进入双栏并开启段落联动。滚动中文时英文跟到对应段落；想把一栏停在别处查图或比较上下文时，可以随时关闭联动，再按需要对齐或重新开启。

| 取舍 | 阅读时的表现 |
|---|---|
| 保留双栏布局与续读 | 初始左英文、右中文，允许交换左右、拖动栏宽，字号跟随 Obsidian。重开时恢复布局和阅读位置。只有英文时可以单栏读。 |
| 保留正文导航 | 图与图注就近查看，引用可跳转，脚注可返回。两栏共用一个可折叠大纲，默认跟随正在读的一栏；有可靠对应标题且联动开启时，两栏一起跳转。 |
| 合并进入对照阅读的操作 | 已确认配对的论文直接打开；手动选择文件收进“更换对照文件”。缺少可靠配对时允许独立滚动，关闭按全文百分比自动带动另一栏的行为。 |
| 合并选区操作 | 继续使用同一个批注面板，支持只标色、加备注、摘录或请求 AI 解释。保留所选语言和准确位置，能从批注回到原句。 |
| 收起低频选项 | 标题常显，作者和 DOI 等属性按需展开。悬停段落高亮维持可选，Markdown 与 PDF 对照、正文与图片分栏归入其他阅读方式。逐句悬停匹配继续暂缓。 |

验收场景：在文献库打开一篇已翻译的论文，直接从中文读到结果段，英文跟到对应段落；关闭联动后能把英文留在结果段，单独滚动中文查图注；再次对齐后继续读，下次打开能回到阅读位置。

## 2026-11-19　理解文献（已明确的使用需求）

- **自己读，通过批注提问。** 用户可以选中词、句或段落，自由向 AI 提问。同一选区支持两种解释深度：用两三句中文讲清所选内容在这里是什么意思；结合前后文和全文论证，解释作者为什么在这里写这句话，以及它对全文结论起什么作用。涉及全文作用时，应指出判断所依据的段落、图表或方法；如果该句只起背景或过渡作用，也应如实说明。
- **让 AI 带读全文。** 默认按论文的论证顺序讲解：作者想解决什么 → 怎么研究 → 哪几张图支撑结论 → 结论能说到哪里。每一步都带用户查看对应原文；讲到关键图时定位相应图、图注和作者解读，讲到结论边界时指出适用条件与局限。论文主要依靠表格或文字论证时，定位实际承载证据的位置。

两种用法都属于核心需求。批注解释默认先显示两三句简短释义，需要时由用户在同一条批注里展开上下文解释，继续查看这句话在段落和全文论证中的作用。论文带读思维导图已确定保留，其展示方式与每次带读的篇幅待讨论。

## 2026-11-19　查找知识点（已确认的产品方向）

保留“找回片段”和“让 AI 根据库内文献回答”两种用法。输入关键词或问题后，默认先显示自己读过、标过或问过的相关片段，能看到所属论文并回到原处。用户主动选择库内文献问答时，再生成带文献依据的回答。

建议在结果里区分英文原文、中文译文、个人备注和 AI 解释；同一段的中英文可以放在同一条结果里。已读优先应依据可定位的阅读记录。只知道某篇论文曾打开过时，保留论文级记录，不把全篇段落都标成已读。其他库内正文命中仍可查看。过去的批注和回答可用来找回问题，新的科学结论应能追溯到对应论文的文字、图或表。

验收场景：搜索曾在译文中问过的术语，先看到当时的选段、问题和所属论文，点开回到对照阅读的位置；想知道其他论文怎样使用该术语时，再让 AI 查库内文献，并能从回答返回相应出处。

## 四个目标的功能取舍（产品方向已确认）

下表作为后续设计依据。“移除”针对列明的功能或日常操作步骤，“收起”表示保留按需使用的入口。表中注明待定的事项继续单独讨论。

| 目标 | 保留 | 合并 | 建议移除或收起 |
|---|---|---|---|
| 存储文献 | 直接读取外部文献目录、书目查找、图文与译文识别、阅读记录与来源关联 | 同一文献条目打开已有原文、译文、图片和批注，翻译完成后沿用原条目 | 网页剪藏流程移除复制、二次登记、重复获取与转换、自动生成 Wiki；独立 PDF 与 MinerU 作为备用 |
| 阅读文献 | 中英双栏、中文滚动时英文按段跟随、一键解除联动、续读、图注与脚注导航 | 一键打开已配对文献，共用大纲；标色、备注、摘录和提问共用选区面板 | 移除可靠配对后的重复选文件、缺乏可靠配对时按全文百分比自动联动；属性、悬停高亮及 PDF 对照收起 |
| 理解文献 | 批注自由提问与全文带读并列；短释义可展开上下文，全文讲解逐步回到原文依据；保留主题学习、自评与带读思维导图 | 概览作为带读起点，阅读助手和连续追问在当前论文内完成，可选择有价值的内容存入本篇笔记 | 一次性精读报告按需生成；主题学习、自评与导图如何融入阅读流程见第 12、13 项建议 |
| 查找知识点 | 默认先看读过、标过、问过的相关片段，按需从库内文献生成回答，能回到出处 | 一个搜索入口覆盖正文、译文、批注、已保存的问答和知识笔记，可限定当前论文或全库 | 移除每次搜索自动生成答案、综述或新页的设计；联网搜索退出默认流程，语义检索和重排配置收进设置 |

## 外围功能决策与影响清单

2026-11-19 已确认全部 13 项的取舍。第 7、8、9、12、13 项确定保留并适配现有使用流程，表中这五项的具体调整供实施时参考。先移除不需要的功能，再完善保留项，按独立改动验证、提交与推送。

| 项目 | 现在的用途 | 收起后可放哪里 | 移除的影响 |
|---|---|---|---|
| 1. Python/R 代码练习（确定移除，待实施） | 在 Obsidian 中逐格运行代码、查看输出、保存练习笔记 | 已选择移除该功能 | 实施后将无法在插件里运行或重跑练习；已有 Markdown 练习笔记仍可阅读。 |
| 2. 配套代码阅读与分析（确定保留，后续再修改） | 阅读 Python/R 项目，按文件、行号追问论文作者的实现；工具包还可生成项目和脚本说明 | 具体入口和交互留待后续讨论 | 若移除，将失去从插件核对作者实现并定位到源码行的能力。代码阅读复用资料带读的会话与追问组件。 |
| 3. R 与 Linux 专门索引（确定收起入口，保留索引页） | 分类浏览 R 包、函数、命令、软件、文件格式和操作示例 | 日常统一从“查知识点”检索两类笔记正文；两份索引页保留在 Obsidian，供按类浏览 | 删除索引页会失去分类浏览能力，因此只收起专门入口。 |
| 4. 工作台统计（确定保留，首页主次已定） | 现有统计展示论文处理深度分布、笔记数量和近期文件修改热力图 | 首页首要展示本周读过哪些论文、上次读到哪里，方便继续阅读；文献总数和可中英对照的篇数放在次要位置。 | 失去本周阅读与文献库规模的概览。阅读日历等其他指标尚未决定。 |
| 5. 待处理中心（确定移除独立中心，待实施） | 现有中心跨论文汇总未完成事项和需复查的来源，并跳回相关记录 | 文献库保留“需处理”筛选。具体问题回到对应论文、批注或原操作记录处理；尚未关联论文的失败记录也能通过筛选找到。 | 独立的分阶段待办总表退出。只有英文的论文和仅供回看的摘录属于正常阅读状态，无需自动列为待办。 |
| 6. 知识库体检（已确认） | 只读检查 Wiki 断链、属性、孤立页和索引问题 | 收起工作台入口，保留手动只读体检和已有写后检查。只有影响阅读、定位或找回内容的问题才进入文献库“需处理”筛选，其余发现留在维护报告。 | 无法主动扫描全库问题。旧 Dashboard 的部分 AI 写入也调用体检做后置检查。 |
| 7. 体检后的 AI 修复（保留，调整待定） | 根据体检报告处理低风险问题，再检查修复结果 | 建议从具体问题或体检报告发起，展示受影响的笔记与拟议改动。原文或批注位置不确定时让用户核对。 | 体检仍可报告问题，用户需要手动改笔记或索引。 |
| 8. 多模型与环境诊断（保留，调整待定） | 检测连接、CLI 和工具路径，刷新模型列表，部分后端可查看额度 | 建议批注、带读、库内问答各自沿用已选模型；出错时就地显示与本次任务有关的诊断，完整配置放在设置里。 | 减少定位模型或运行环境故障的手段。基本模型连接和凭据配置仍是批注提问、AI 带读、库内问答的依赖。 |
| 9. 整库 OKF 导出（保留，调整待定） | 把 Wiki 转为带规范链接和属性的开放知识格式包，供其他工具读取 | 建议在“维护与导出”中按需发起，标明导出的是 Wiki 知识页。外部文献目录中的原文、译文和图片不属于现有 OKF 导出范围。 | 完全移除后无法在项目内生成 OKF 格式包。原始 Markdown 和单篇学习记录导出独立。 |
| 10. 单篇学习记录导出（确定移除） | 将会话中的一个节点、一条支线或整次带读预览并保存为 Markdown | 移除生成此类导出的入口，保留既有记录 | 仍可保存选中的批注或摘录。主题学习、论文带读和整库 OKF 导出独立保留。 |
| 11. 跨论文综合写页（确定移除） | 将多篇来源围绕一个问题整理成长期比较或综合页 | 移除产品内的跨论文综合写页操作，保留既有页面及其检索能力 | 库内多文献问答与来源引用独立保留。 |
| 12. 独立主题学习与自评（保留，调整待定） | 从主题开始规划路线、讲解、追问并记录理解状态，仍属预览 | 建议既能自行输入主题，也能从论文里的概念或“查知识点”结果开始；主动选择自评后可回到原来的阅读位置。 | 失去脱离具体文献学习某个主题的流程。论文带读继续需要路线、提问和进度等共用能力。 |
| 13. 论文带读思维导图（保留，调整待定） | 将讲解与追问展示为节点和支线，支持定位并重开旧问题 | 建议在带读中按需展开，以“研究问题 → 方法 → 关键图表 → 结论边界”为主线，追问挂到相应步骤；从节点回看对应原文或图表。 | 失去按问题关系回顾长会话的方式。现有导图还承载节点导航。 |
